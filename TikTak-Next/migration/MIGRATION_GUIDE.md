# מדריך בטיחות ומעבר עתידי (Safety Protocol & Future Cutover Guide)

מדריך זה מגדיר את הנהלים המחייבים ואת נקודת העצירה הבטיחותית לפני כל ביצוע מעבר נתונים.

---

## 🛑 1. נוהל נקודת עצירה מחייבת (Mandatory Stop Protocol)

לפני ביצוע כל אחת מהפעולות הבאות:
- חיבור למסד הנתונים הקיים של Production
- ייבוא נתוני Production
- שינוי Deployment קיים או Domain קיים
- העברת משתמשים פעילים
- החלפת המערכת הקיימת
- ביצוע Migration בפועל

**חובה לעצור באופן מוחלט ולהציג למשתמש:**
1. **מה הפעולה המתוכננת**
2. **אילו נתונים היא עלולה להשפיע**
3. **כיצד יבוצע גיבוי לפני הפעולה**
4. **כיצד ניתן לבצע Rollback מלא בלחיצת כפתור**
5. **אילו בדיקות אימות (Verification Tests) יבוצעו לפני המעבר**

---

## 💾 2. נוהל גיבוי מוקדם (Backup Protocol)

1. יצירת Export מלא של בסיס הנתונים הקיים לקובץ JSON/Firestore Dump מבודד.
2. שמירת הגיבוי בתיקייה מוגנת (`/backups/backup_YYYYMMDD_HHMMSS.json`).
3. אימות גודל הקובץ ומספר הרשומות בגיבוי בהשוואה ל-Production.

---

## ↩️ 3. נוהל שחזור (Rollback Procedure)

במקרה של תקלה במהלך העברה עתידית:
1. ניתוק מיידי של API / DB Write access מ-TikTak Next.
2. החזרת ה-DNS / Hosting Redirect אל המערכת הקיימת (TikTak v1 Production) ללא אובדן נתונים.
3. שחזור נתונים מהגיבוי המאומת.
